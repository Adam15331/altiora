# Ireland: Trinity College Dublin and University College Dublin — non-EU entry requirements

Research report only — nothing in the data, code, pages, engine or hashes was changed. Read 2026-10-21.
Naming: "IE" here is the **country code for Ireland**. IE University (Spain) is reported separately in `research/ie-university.md`.

**Method.** Non-EU international direct-application route only. CAO points (the domestic/EU route, whose cut-offs move every year) are never recorded as a requirement; where mentioned they appear only in notes, labelled CAO. Every non-NOT-PUBLISHED cell and every requirement claim carries its official source URL, access date and a verbatim `sourceSnippet`, checked mechanically against the saved page text. States: ACCEPTED (with this course's published minimum), ACCEPTED WITH CONDITIONS (not standalone, or only with extra steps), NOT ACCEPTED (an official page says so), NOT PUBLISHED (silent, ambiguous, blocked or unreadable — never a rejection). A university-wide minimum is labelled "university-wide". No third-party evidence; no proxy, text reader, cache, mirror or archive was used.

**User-agent note.** The fetch script sent a browser User-Agent header by default (removed 2026-10-21; see `research/user-agent-audit.md`). Every page used as evidence was re-requested on 2026-10-21 without that header. Every Trinity page still loads, so none of its access depended on the header. Every UCD page returns HTTP 403 without it, so all UCD content was discarded as evidence and UCD is reported as blocked (section 5).

The card copy (6345) reads: "◔ Your subjects fit, but this course doesn't publish a grade requirement we can compare … so we can't confirm it's a match." That is honest, though it does not say *test/interview decides*.
2. **Subject-only mode** (no complete grade profile): only `classify` runs. `essential: []`, `preferred: []` without `noSubjectRequirements` hits the field-relevance guard (1192-1205), so the course gets red or amber unless the student has the field's core subjects, and green only then. With `noSubjectRequirements: true` (validated at validate-requirements.mjs:280-287: needs empty essential/preferred and a **verified, quoted** subjectPrerequisites row) the course is green "Subjects fit" for everyone, then `unconfirmed` once grades are set.
3. **AP students**: they are exempt from the grade gate, but the AP cap (5710-5713) holds green at amber unless `apRequirementMet(course)`, and `apRequirement` is null for a new course (cR.js:4793). The **US elite "reach" (4596) does not apply** because it is keyed to `country === 'US'`.
5. **IB HL**: with `ibHL: []` there is no warning (5739-5762).

Caveats:
- The "holistic / no fixed offer" wording (2673, 4405, 6114) is US only, so IE University shows "not published" instead.
- If an IE/ES record holds an A-Level/IB figure that is only an *indicative or conditional* number, the engine treats it as a hard offer and produces green, grey, safety or reach. It must stay null in the engine; text can go in the panel `detail` or `note`, never `typicalOffer`/`overallScore` (§3 coupling).
- `admissionTests` codes render as "X required". An interview has no code; it goes in `otherRequirements` items or `notes`.
